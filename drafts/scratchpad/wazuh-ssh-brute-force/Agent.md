### **SSH Connection**
### Fix: SSH Port Forwarding via VirtualBox NAT Network (`WazuhLab`)

#### 1. Enable OpenSSH on Debian Guest (TTY)

Bash
```
# Install and enable SSH service
sudo apt update && sudo apt install -y openssh-server
sudo systemctl enable --now ssh
```

#### 2. Configure Port Forwarding on Fedora Host

Forward host port `2223` to the Debian guest's internal NAT Network IP (`10.10.10.5:22`):

Bash

```
# Add port-forwarding rule to the WazuhLab NAT Network
VBoxManage natnetwork modify --netname WazuhLab --port-forward-4 "ssh-debian:tcp:[127.0.0.1]:2223:[10.10.10.5]:22"

# Verify the Fedora host is actively listening on port 2223
ss -tulpn | grep 2223
```

#### 3. Connect via SSH from Fedora Host

Bash

```
ssh -p 2223 <debian-username>@127.0.0.1
```

### Deploying an Agent

Documentation: https://documentation.wazuh.com/current/installation-guide/wazuh-agent/wazuh-agent-package-linux.html

```
apt-get install gnupg apt-transport-https curl

```


## Connecting an Agent
### Troubleshooting Summary: Wazuh Agent Version Conflict & Schema Resolution

---

#### 1. Symptom & Initial Failure

After configuring SSH port forwarding and deploying `wazuh-agent` on the Debian Minimal target (`10.10.10.5`), the agent failed to appear on the Wazuh Manager dashboard. Inspecting `/var/ossec/logs/ossec.log` revealed registration rejection from `wazuh-authd`:

```text
wazuh-agentd: ERROR: Agent version must be lower or equal to manager version (from manager)
wazuh-agentd: ERROR: Unable to add agent (from manager)
```

* **Root Cause:** Wazuh strictly enforces that agent versions must not exceed the manager's version. The Debian target had installed a newer minor/patch build than the manager.
* **Side Effect:** Enrollment halted, leaving `/var/ossec/etc/client.keys` empty.

---
#### 2. Agent Downgrade

To align the agent with the manager:

1. **Queried Available Repository Builds:**
```bash
apt-cache madison wazuh-agent
```

2. **Forced Downgrade & Version Pinning:**
```bash
sudo systemctl stop wazuh-agent
sudo WAZUH_MANAGER='10.10.10.10' WAZUH_AGENT_NAME='debian-target' \
  apt-get install --allow-downgrades -y wazuh-agent=<MANAGER_VERSION>
sudo apt-mark hold wazuh-agent

```

---

#### 3. Post-Downgrade Schema Errors (`ossec.conf`)

Following the downgrade, `wazuh-agent.service` failed to start with exit code 1. Inspection with `journalctl` and `wazuh-modulesd -t` identified leftover XML tags generated by the newer release that the downgraded parser could not process:

* **Error 1:** `ERROR: No such tag 'users' at module 'syscollector'`
* **Error 2:** `ERROR: No such tag 'services' at module 'syscollector'`

##### Resolution:

Removed unrecognized tags from `/var/ossec/etc/ossec.conf`:

```bash
sudo sed -i '/<users>/d' /var/ossec/etc/ossec.conf
sudo sed -i '/<groups>/d' /var/ossec/etc/ossec.conf
sudo sed -i '/<services>/d' /var/ossec/etc/ossec.conf

```

Validated configuration syntax on the agent:

```bash
sudo /var/ossec/bin/wazuh-modulesd -t
sudo /var/ossec/bin/wazuh-agentd -t

```

*(Both commands returned code 0 with no syntax errors).*

---

#### 4. Enrollment & Service Startup

With the configuration sanitized:

1. **Triggered Direct Key Exchange (if unpopulated):**
```bash
sudo /var/ossec/bin/agent-auth -m 10.10.10.10 -p 1515 -A debian-target

```


2. **Restarted the Agent Service:**
```bash
sudo systemctl daemon-reload
sudo systemctl restart wazuh-agent
sudo systemctl enable wazuh-agent

```



---

#### 5. Final Connection Verification

##### On Debian Target (`10.10.10.5`):

* Verified key population:
```bash
sudo cat /var/ossec/etc/client.keys
# Output: 001 debian-target any <BASE64_KEY>

```


* Confirmed active telemetry stream:
```bash
sudo tail -n 25 /var/ossec/logs/ossec.log | grep "Connected to the server"
# Output: INFO: (4102): Connected to the server (10.10.10.10:1514/tcp)

```


* Verified socket state:
```bash
sudo ss -tanp | grep 10.10.10.10:1514
# Output: ESTAB

```



##### On Wazuh Manager (`10.10.10.10`):

```bash
sudo /var/ossec/bin/agent_control -l

```

The agent `debian-target` transitioned to **Active** status.
